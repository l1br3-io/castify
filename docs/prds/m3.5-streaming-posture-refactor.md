# PRD: M3.5 — Streaming Posture Refactor

> **Status:** ✅ Complete — audit confirmed Drive playback is smooth; no fix required. Instrumentation shipped permanently.
> **Companion:** [`ROADMAP-self-hosted-media-server.md`](../ROADMAP-self-hosted-media-server.md), [`VISION.md`](../VISION.md), [`m3-play.md`](./m3-play.md).
> **Audit report:** [`tasks/m3.5-audit-report.md`](../../tasks/m3.5-audit-report.md)

## Purpose

M3.5 does two things in one milestone:

1. **Doc reframe** — replace the cost-driven streaming prohibitions inherited from the old "hosted service" framing with a UX-first posture that fits self-hosted hardware. The user owns the server; server bandwidth, CPU, and disk are free. We pick the smoothest path per provider.
2. **Drive stutter root-cause + fix** — the user has observed real playback stutter on Google Drive content. The proxy path (`/api/videos/{id}/stream`) and the stream-url resolution path (`/api/videos/{id}/stream-url`) both need instrumentation and audit. Whatever the audit finds gets fixed in this milestone.

This is the foundation for every later milestone (M4 disk cache, M6 transcoding). All later work assumes a fast, observable proxy.

## In scope

- **Doc edits** across 5 files:
  - [`docs/data-storage-principles.md`](../data-storage-principles.md) — rewrite anti-pattern #2 ("Never proxy bytes") into a UX-first rule
  - [`docs/VISION.md`](../VISION.md) — drop "Server-side video transcoding — ever" from non-goals
  - [`docs/prds/m3-play.md`](./m3-play.md) — soften transcoding non-goal; update streaming architecture notes with UX-first framing
  - [`docs/ROADMAP.md`](../ROADMAP.md) — link to the self-hosted media server roadmap
  - [`docs/config.md`](../config.md) — placeholder section for upcoming M4–M8 env vars
- **Code comment reframe** in two locations:
  - `crates/api/src/routes/videos.rs:546-554` — `get_stream_url` doc comment
  - `frontend/src/api/types.ts:219-228` — `StreamUrlDto` comment
- **Drive stutter audit** — instrument `/stream` and `/stream-url` with structured timing logs (TTFB, throughput, seek RTT, token-refresh occurrences). Reproduce the stutter on real Drive content. Capture measurements.
- **Fix what the audit finds**. Likely candidates (verify, don't assume):
  - Per-request `http_download` client construction (no connection pooling)
  - Body buffering configuration in reqwest (currently streams, but default buffer sizes may be wrong for video)
  - Range passthrough correctness on rapid seek (does each seek cleanly cancel the prior request?)
  - Token refresh races (mid-stream 401 — does the refresh block the active response?)
  - Direct-URL expiry window (currently 50 min, may be too aggressive or not aggressive enough)
- **Drive default strategy decision** — based on audit findings, decide between:
  - (a) Status quo: try `?alt=media` redirect first, fall back to `/stream` proxy
  - (b) Always proxy Drive (give up the direct path entirely for consistency)
  - (c) Config knob: `CASTIFY_DRIVE_STRATEGY=auto|direct|proxy`
- **Bench crate extensions** — new scenarios in `crates/bench/`:
  - `/stream` sustained throughput (MB/s over a fixed-duration sample)
  - `/stream` seek latency (random Range requests, p50 + p99)
  - `/stream-url` resolution latency (p50 + p99)
- **New e2e tests** in `crates/api/tests/videos.rs`:
  - Drive inline-byte fallback path (mock Drive returning 200 with bytes instead of 302 redirect)
  - Token-refresh-during-stream scenario (mock Drive returning 401 mid-stream)

## Out of scope (deferred)

- Hot video disk cache — that's M4.
- ffmpeg integration — that's M5.
- Transcoding, adaptive bitrate, subtitle burning — M6/M7/M8.
- Changes to OneDrive or Dropbox streaming paths (already smooth per user feedback).
- Frontend player UI changes (the `<video>` element and controls are correct; the issue is upstream in the proxy).
- New `Strategy` variants in `StreamUrl` (the existing `Direct` / `Proxied` enum is sufficient).

## Architecture decisions (locked)

| Area                                | Choice                                                                                                                                                                                                                                                                                                                                              |
| ----------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Streaming posture (docs)**          | UX-first per provider. Default to whatever path delivers the smoothest playback for that provider. OneDrive + Dropbox keep their native direct CDN URLs (already smooth). Google Drive keeps direct-first / proxy-fallback, unless audit reveals proxy should be the default. Anti-pattern #2 in `data-storage-principles.md` rewritten from "never proxy bytes" to "pick the smoothest path; self-hosted means server bandwidth is free." |
| **Audit methodology**                 | Structured `tracing` spans on `/stream` and `/stream-url` with: `ttfb_ms` (time-to-first-byte), `throughput_mbps` (rolling), `seek_rtt_ms` (per Range request), `token_refreshed: bool`. Logs at `info` level for steady-state, `debug` for per-Range detail. Reproduce stutter with a real Drive video ≥ 1 GB; capture 10 minutes of playback including 5 seeks. |
| **Fix scope**                          | Whatever the audit identifies as the dominant contributor to stutter. No "nice-to-have" rewrites — only the root cause. If the audit is inconclusive, the fix becomes "add the missing instrumentation and ship the doc reframe; M3.5 exits with the audit published as a report." |
| **Drive default strategy decision**   | Decision is **data-driven from the audit**, not pre-committed. The audit report ends with a recommendation between (a), (b), or (c) above, with measurements backing the choice. |
| **Backward compatibility**            | Zero behavioral changes for OneDrive + Dropbox users. Drive users see only improvements (or no change if the audit finds the existing implementation is fine and the user's stutter had a different cause). |

## Functional requirements

### FR-1: Documentation reframe

- **FR-1.1** `docs/data-storage-principles.md` anti-pattern #2 ("Server byte proxying") is rewritten. The new rule: "Pick the smoothest path per provider. Direct when the provider's native URL works in-browser; proxy when it doesn't. Self-hosted means server bandwidth is free — never apologize for using the proxy when it gives better UX."
- **FR-1.2** `docs/VISION.md` "Across all phases — NOT building" list drops "Server-side video transcoding — ever." Replaced with a softer statement: "Server-side transcoding — out of launch scope; revisit when codec coverage becomes a real blocker. See [self-hosted media server roadmap](./ROADMAP-self-hosted-media-server.md)."
- **FR-1.3** `docs/prds/m3-play.md` "Out of scope" section's transcoding prohibition is rewritten to match FR-1.2. The streaming-architecture table cell is updated to reflect UX-first framing.
- **FR-1.4** `docs/ROADMAP.md` gains a "What's next" section linking to `ROADMAP-self-hosted-media-server.md`.
- **FR-1.5** `docs/config.md` gains a "Media server features (M4–M8)" section listing all upcoming env vars with a note that they're not yet implemented.
- **FR-1.6** `crates/api/src/routes/videos.rs` doc comment on `get_stream_url` (currently lines 546–554) is rewritten from "off the server entirely" framing to "picks the smoothest path per provider" framing.
- **FR-1.7** `frontend/src/api/types.ts` comment on `StreamUrlDto` (currently lines 219–228) is rewritten to match.

### FR-2: Audit instrumentation

- **FR-2.1** `/stream` handler gains a `tracing::instrument`-style span with fields: `video_id`, `ttfb_ms` (recorded when first byte is flushed), `total_bytes`, `duration_ms`, `throughput_mbps` (computed on response end).
- **FR-2.2** `/stream-url` handler gains a span with: `video_id`, `strategy` (direct/proxy), `resolve_ms`, `token_refreshed: bool`.
- **FR-2.3** Each Range request within a sustained `/stream` connection logs `seek_rtt_ms` at `debug` level (per-request would flood at `info`).
- **FR-2.4** Logs are structured (not string-interpolated) so they're parseable for the audit report.
- **FR-2.5** Instrumentation adds < 1% overhead. No allocations on the hot path.

### FR-3: Audit execution

- **FR-3.1** A real Google Drive video ≥ 1 GB is played for 10 minutes with 5 seeks. Instrumentation captures the session.
- **FR-3.2** The audit report documents: TTFB distribution, sustained throughput, per-seek RTT, any token refreshes, any error responses, observed stutter timestamps (correlated with logs).
- **FR-3.3** Root cause is identified OR the report concludes "instrumentation is insufficient; specific follow-up needed." The latter is an acceptable outcome — guessing is not.
- **FR-3.4** The audit report lives at `tasks/m3.5-audit-report.md` (not under `docs/` — it's task-output, not living documentation).

### FR-4: Fix implementation

- **FR-4.1** Whatever the audit identifies as the dominant stutter contributor is fixed. Scope is the audit's finding, nothing more.
- **FR-4.2** If the audit finds multiple contributing factors, the report prioritizes them and M3.5 fixes the top one. Lower-priority factors become follow-ups (M3.6 or folded into M4).
- **FR-4.3** The fix is covered by a new e2e test that would have failed before the fix (regression protection).

### FR-5: Drive default strategy

- **FR-5.1** The audit report recommends one of: (a) status quo, (b) always proxy, (c) config knob. The recommendation is implemented.
- **FR-5.2** If (a): no code change; the recommendation is documented in the audit report.
- **FR-5.3** If (b): `GoogleDriveProvider::open_stream_url` returns `StreamUrl::Proxied` unconditionally. The `resolve_direct_download_url` path is removed (or kept behind a `#[cfg(test)]` gate for diagnostic use).
- **FR-5.4** If (c): new env var `CASTIFY_DRIVE_STRATEGY=auto` (default). New config field on `Config`. `GoogleDriveProvider::open_stream_url` consults the strategy.

### FR-6: Bench crate extensions

- **FR-6.1** `crates/bench/src/bin/run.rs` gains three new scenarios (or a new binary `bench-stream`):
  - `stream_throughput` — sustained `/stream` throughput over 60s sample
  - `stream_seek_rtt` — random Range requests, p50 + p99
  - `stream_url_resolve` — `/stream-url` resolution latency, p50 + p99
- **FR-6.2** Scenarios run against the existing `e2e` mock factory (no real provider needed for steady-state measurements).
- **FR-6.3** Results printed in the same format as existing bench scenarios.

### FR-7: E2E test coverage

- **FR-7.1** New test `stream_drive_inline_byte_fallback`: e2e mock Drive returns 200 with bytes (instead of 302 to CDN). `/stream-url` returns `strategy: "proxy"`; `/stream` returns 206 with correct `Content-Range`.
- **FR-7.2** New test `stream_token_refresh_mid_stream`: e2e mock Drive returns 401 on first Range request, succeeds on retry after refresh. `/stream` returns 206 correctly; token refresh logged.
- **FR-7.3** Existing `stream_*` tests continue to pass.

## Risks

| Risk                                                | Impact | Mitigation                                                                                                              |
| --------------------------------------------------- | ------ | ----------------------------------------------------------------------------------------------------------------------- |
| Audit is inconclusive — stutter doesn't reproduce   | High   | Ship the instrumentation + doc reframe anyway. The audit report documents what was tested and what would need to be tested next. M3.5 exits with the instrumentation landed; the fix becomes M3.6. |
| Root cause is upstream (Google rate-limiting)       | High   | If the audit shows Drive-side rate-limit responses (429 with `Retry-After`), the fix becomes "implement M4 disk cache as the primary path" — promoted to M3.5 if scope allows, else M3.5 exits with the diagnosis and M4 starts immediately. |
| Fix requires touching provider trait                | Med    | Acceptable if scoped to `GoogleDriveProvider`. Avoid touching the trait itself.                                          |
| Fix uncovers a deeper architectural issue            | Low    | Document in audit report; defer to M4 if scope is too large for M3.5.                                                    |
| Instrumentation itself causes stutter                | Low    | Measurement is gated behind `tracing` levels; production at `info` is low-volume. Bench before and after to verify.       |
